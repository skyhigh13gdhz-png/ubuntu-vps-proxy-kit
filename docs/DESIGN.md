# V1 设计说明

## 项目目标

目标用户不是 Linux 运维人员，而是拿到一台崭新 Ubuntu VPS、希望快速完成服务器环境准备和代理节点部署的小白。

因此项目优化的不是“命令最少”，而是：

- 少做重复的人肉操作；
- 先判断问题属于 VPS、网络、服务还是客户端；
- 自动安装缺失的基础命令；
- 出错时留下可读报告；
- 不把不可验证的事情伪装成“自动检测成功”。

## 分层

### Layer 1：VPS 基础环境

检测 Ubuntu 版本、CPU 架构、内存、磁盘、DNS、公网 IPv4、HTTPS 出站、监听端口、防火墙。

### Layer 2：代理服务

检测/安装 3x-ui 与 Xray，检查 systemd 服务和监听状态。

### Layer 3：节点配置

V1 推荐 VLESS + Reality。配置仍由用户在 3x-ui 中确认，避免脚本未经用户确认直接暴露入口、写入随机面板凭据或覆盖已有配置。

### Layer 4：真实客户端

最终验证必须来自真实客户端。服务器自身无法仅通过 ping 或 curl 证明某个中国大陆网络当前可以反向到达服务器的某个端口。

## 为什么不强制“临时 TCP 网页测试”

此前考虑过让脚本临时启动 listener，再让大陆手机关闭 VPN 后访问 VPS。这个办法对定位“客户端 -> VPS TCP 入站”有价值，但它增加操作步骤，而且最终客户端本身就要进行真实连接测试。

所以 V1 将它降级为 **高级排障手段**，不放进默认安装路径。

## 安装策略

`diagnose.sh`：允许安装诊断所需的基础命令，但不安装/修改代理服务。

`install.sh`：安装缺失依赖；如果已经检测到 x-ui，则默认停止覆盖安装，保护现有环境。

`verify.sh`：安装后只验证服务器可观察到的状态。

`collect-report.sh`：收集系统、端口、服务日志和出站结果，并对公网 IPv4 做基础脱敏。

## 后续版本

V1 稳定后再考虑：

- 自动生成/校验 Reality 参数；
- 交互式创建入站；
- 多 VPS 厂商/网络基准；
- 可选的大陆外部探针；
- 自动更新与回滚；
- 更严格的报告脱敏；
- ShellCheck / CI；
- 自动化集成测试。
